2.4 DDA 文字说明（粘贴到报告，放在两张截图之后）
  ─────────────────────────────────────
  DDA（Digital Differential Analyzer，数值微分法）基于直线的斜截式方程
  y=kx+b，采用增量思想。算法先计算 dx 和 dy，取绝对值较大的作为步数
  steps，然后计算 x 和 y 每步的增量（xIncrement = dx/steps，
  yIncrement = dy/steps）。每次迭代将坐标四舍五入后调用 SetPixel
  逐像素绘制。优点是能处理任意斜率的直线，缺点是浮点运算较多。
  ─────────────────────────────────────

3.3 中点算法文字说明
  ─────────────────────────────────────
  中点画线算法基于直线的一般式方程 F(x,y)=ax+by+c。其中 a=y1-y2，
  b=x2-x1。判别式 d=2a+b，d1=2a，d2=2(a+b)。每次迭代判断 d 的符号：
  若 d<0 表示中点在直线下方，取右上像素(x+1,y+1)，d 加 d2；
  若 d≥0 表示中点在直线上方，取右像素(x+1,y)，d 加 d1。
  全部使用整数运算，效率比 DDA 高。
  ─────────────────────────────────────

4.3 Bresenham 文字说明
  ─────────────────────────────────────
  Bresenham 算法通过比较交点与下方最近像素的距离 d 来决策。初始决策
  参数 p=2dy-dx。每次 x 递增后判断 p：若 p<0 则 y 不变，p 累加 2dy；
  若 p≥0 则 y 递增，p 累加 2(dy-dx)。该算法完全使用整数加减和移位运算，
  避免了 DDA 的浮点运算和中点算法的乘法，是三种算法中效率最高的。
  ─────────────────────────────────────

第五步：三种算法对比总结（重要，放在报告最后）
============================================================

  以下文字可直接用到报告的分析部分：
  ─────────────────────────────────────
  三种算法均成功绘制了从(100,100)到(600,400)、斜率k=0.6的直线，
  但它们的内部实现原理各不相同：

  DDA 采用浮点增量计算，每步需要一次浮点加法，思路最直观但运算量最大；
  中点算法改用整数判别式 d，避免了浮点运算，每次迭代只需整数加减；
  Bresenham 算法进一步优化，只用一个决策参数 p 和简单的整数加减，
  是公认的直线绘制最优算法，被广泛应用于显卡硬件中。

  三种算法的对比如下表：
  
  算法        │ 核心变量    │ 运算类型 │ 每次迭代操作
  ───────────┼────────────┼─────────┼──────────────
  DDA        │ k, xInc, yInc │ 浮点    │ 浮点加法 + 四舍五入
  中点        │ d, d1, d2     │ 整数    │ 比较 + 整数加法
  Bresenham  │ p              │ 整数    │ 比较 + 整数加法（极少）
  ─────────────────────────────────────

第七步：实验总结（个人心得）
============================================================

  ─────────────────────────────────────
  在本次直线扫描算法实验中我深入学习了DDA、中点和Bresenham三种
  直线生成算法，并在MFC环境中亲手编码实现了这些算法。三种算法
  全部使用SetPixel逐像素绘制，真正理解了"点画线"的基本原理——
  直线在光栅显示器上本质是一系列离散像素点的集合。

  通过对比三种算法我体会到：DDA最直观但需要浮点运算，中点算法
  用整数判别式消除了浮点，而Bresenham只用一个决策参数便实现了
  最高效的绘制。从DDA到Bresenham的演进过程，体现了算法优化的
  核心思想——"用更少的运算量达到同样的效果"。

  实验过程中我也加深了对MFC消息映射机制的理解：菜单命令通过
  ON_COMMAND宏绑定到处理函数，处理函数设置标志位后调用Invalidate
  触发OnDraw重绘，这种模式贯穿了整个MFC图形编程。
  ─────────────────────────────────────
